## Pick your starter

Each example is a complete, runnable service with a `docker compose up` quick-start.
Choose the domain that matches your use case and the agentic response type you need.

| Example | Domain | Agentic response demonstrated | Port | Main endpoint |
|---|---|---|---|---|
| [`examples/store/`](https://github.com/ai-mpathyminds/yaagents/tree/main/examples/store) | E-commerce recommendations | `clarification_required` (no purchase history) | 8121 | `POST /products/{id}/recommendations` |
| [`examples/store-go/`](https://github.com/ai-mpathyminds/yaagents/tree/main/examples/store-go) | E-commerce recommendations (Go) | `clarification_required` (no purchase history) | 8121 | `POST /products/{id}/recommendations` |
| [`examples/campaign-api/`](https://github.com/ai-mpathyminds/yaagents/tree/main/examples/campaign-api) | Campaign optimization | `success` · `clarification_required` | 8121 | `POST /campaigns/{id}/optimizations` |
| [`examples/campaign-api-go/`](https://github.com/ai-mpathyminds/yaagents/tree/main/examples/campaign-api-go) | Campaign optimization (Go) | `success` · `clarification_required` | 8121 | `POST /campaigns/{id}/optimizations` |
| [`examples/customer-support-triage/`](https://github.com/ai-mpathyminds/yaagents/tree/main/examples/customer-support-triage) | Customer support triage | `clarification_required` (missing context) | 8121 | `POST /tickets/{id}:triage` |
| [`examples/financial-risk-screening/`](https://github.com/ai-mpathyminds/yaagents/tree/main/examples/financial-risk-screening) | Financial risk screening | `approval_required` (high-risk decision) | 8121 | `POST /claims/{id}/risk-screens` |

All examples require the YAAgents Gateway on port 8120. Run `docker compose up` inside
any example directory — the compose file starts both the gateway and the service.

## By agentic response type

**E-commerce recommendations** (`store/`, `store-go/`) — demonstrates the
`clarification_required` (400) response: when a customer has no purchase history,
the service asks the client for anchor items rather than returning empty results.

**Campaign optimization** (`campaign-api/`, `campaign-api-go/`) — demonstrates
`success` (200) for optimization results and `clarification_required` (400)
when the budget delta is ambiguous.

**Customer support triage** (`customer-support-triage/`) — demonstrates
`clarification_required` (400) for missing context: the agent asks for ticket
severity or SLA tier before routing, rather than guessing.

**Financial risk screening** (`financial-risk-screening/`) — demonstrates
`approval_required` (412): when a claim exceeds the auto-approve threshold,
the service returns a structured approval request instead of making the decision unilaterally.

## Multi-service example

The `campaign-api` examples also demonstrate how to chain two yaagents-governed
services via inter-agent calls. See
[inter-agent calls](/yaagents/architecture/inter-agent-calls/) for the gateway
inter-agent routing pattern.
