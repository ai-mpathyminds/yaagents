In 30 minutes you'll build a ticket triage service from scratch:

- `POST /tickets/{id}:triage` — an agentic classify operation (Pattern 3 in [Agentic REST Patterns](/yaagents/explanation/agentic-rest-patterns/))
- Three typed outcomes: `success`, `clarification_required`, `validation_failed`
- Gateway-enforced authentication and audit logging — zero code in your service
- Real curl examples to see it working

This is a **build-it-yourself tutorial**. You write the code; you run it. The service uses a keyword-based mock classifier — no LLM call required to follow along. At the end you'll know where to plug in a real model.

## Prerequisites

- Docker and Docker Compose
- Python 3.11+
- `pip` (or `uv`)
- `git` (to clone the yaagents repo for the gateway config reference)

## Step 3 — Implement the agentic operation

Write the FastAPI app using `@agentic_operation`. The key rule: **never use `@app.post` for the agentic endpoint** — always use `@agentic_operation` + `app.add_api_route`. This ensures OpenAPI metadata, response typing, and gateway header propagation are all wired correctly.

```python title="my-triage-service/src/triage/app.py"
# SPDX-License-Identifier: Apache-2.0
"""Ticket triage service — yaagents Agentic REST Profile v0.3.

POST /tickets/{id}:triage — classifies a ticket by category and severity.

Three typed outcomes:
- success               → ticket is fully-specified; returns triage result
- clarification_required → missing priority_hint; asks the caller
- validation_failed      → ticket ID not found
"""

from __future__ import annotations

from typing import Annotated

from fastapi import Depends, FastAPI
from fastapi.responses import Response

from yaagents_fastapi import (
    AgenticContext,
    AgenticResponse,
    AgenticResponses,
    RequiredInput,
    agentic_operation,
    agentic_route_kwargs,
)

from .data import get_ticket
from .triage import triage

app = FastAPI(
    title="Ticket Triage Service",
    version="0.1.0",
    description="yaagents Agentic REST Profile v0.3 — POST /tickets/{id}:triage",
)

CtxDep = Annotated[AgenticContext, Depends(AgenticContext)]


@agentic_operation(
    resource="TicketTriage",
    operation_kind="analysis",
    mutating=False,
    responses=AgenticResponses(
        success=True,
        clarification_required=True,
        validation_failed=True,
    ),
)
async def triage_ticket(
    ticket_id: str,
    ctx: CtxDep,
) -> Response:
    """Triage a support ticket — categorise, score severity, assign team.

    Returns success for fully-specified tickets; clarification_required
    when priority_hint is absent; validation_failed when ticket not found.
    """
    ticket = get_ticket(ticket_id)

    # validation_failed — ticket does not exist
    if ticket is None:
        return AgenticResponse.validation_failed(
            code="TICKET_NOT_FOUND",
            message=f"Ticket {ticket_id} does not exist.",
            correlation_id=ctx.correlation_id,
            request_id=ctx.request_id,
        )

    # clarification_required — missing priority_hint
    if ticket.get("priority_hint") is None:
        return AgenticResponse.clarification_required(
            required_inputs=[
                RequiredInput(
                    name="priority_hint",
                    location="body",
                    type="string",
                    required=False,
                    question="What is the urgency level?",
                    allowed_values=["low", "medium", "high", "critical"],
                ).to_dict()
            ],
            message=(
                "A priority hint would improve triage accuracy. "
                "Please provide one or re-submit without it to use the default."
            ),
            correlation_id=ctx.correlation_id,
            request_id=ctx.request_id,
        )

    # success — run the mock triage classifier
    result = triage(ticket)
    return AgenticResponse.success(
        body={"triage": result},
        correlation_id=ctx.correlation_id,
        request_id=ctx.request_id,
    )


# Wire the route — note: use app.add_api_route with agentic_route_kwargs,
# NOT @app.post. This ensures OpenAPI + gateway header propagation.
app.add_api_route(
    "/tickets/{ticket_id}:triage",
    triage_ticket,
    methods=["POST"],
    **agentic_route_kwargs(triage_ticket),
    summary="Triage a support ticket",
    tags=["tickets"],
)


@app.get("/healthz", include_in_schema=False)
async def healthz() -> dict[str, str]:
    return {"status": "ok"}


@app.get("/readyz", include_in_schema=False)
async def readyz() -> dict[str, str]:
    return {"status": "ok", "profile": "v0.3"}
```

## Step 4 — Mock triage logic

Write a keyword-based classifier that assigns category, severity, and suggested team without an LLM call. This is your "mock" — easy to replace with a real model call later.

```python title="my-triage-service/src/triage/triage.py"
"""Mock ticket triage logic — keyword-based (no LLM required for this tutorial).

To replace with a real LLM: swap classify_ticket() with an Anthropic / OpenAI
/ LangChain call. Everything else in app.py stays the same.
"""

from __future__ import annotations

_CATEGORY_KEYWORDS: dict[str, list[str]] = {
    "security": ["authentication", "bypass", "password", "exploit", "vulnerability", "injection"],
    "billing":  ["invoice", "billing", "payment", "charge", "subscription", "refund"],
    "performance": ["slow", "latency", "timeout", "cpu", "memory", "bottleneck"],
    "feature":  ["dark mode", "feature request", "add", "would be nice", "could you"],
}

_SEVERITY_MAP: dict[str, int] = {
    "critical": 4,
    "high":     3,
    "medium":   2,
    "low":      1,
}

_TEAM_MAP: dict[str, str] = {
    "security":    "security-response",
    "billing":     "billing-support",
    "performance": "platform-reliability",
    "feature":     "product-backlog",
    "general":     "tier-1-support",
}


def classify_ticket(title: str, description: str) -> str:
    """Return the best-matching category for the ticket text."""
    text = (title + " " + description).lower()
    scores = {
        category: sum(1 for kw in keywords if kw in text)
        for category, keywords in _CATEGORY_KEYWORDS.items()
    }
    best = max(scores, key=lambda c: scores[c])
    return best if scores[best] > 0 else "general"


def triage(ticket: dict) -> dict:
    """Return the triage result for a fully-specified ticket."""
    category = classify_ticket(ticket["title"], ticket["description"])
    priority_hint = ticket.get("priority_hint", "medium")
    severity_score = _SEVERITY_MAP.get(priority_hint, 2)

    return {
        "ticket_id": ticket["id"],
        "category": category,
        "severity": priority_hint,
        "severity_score": severity_score,
        "suggested_team": _TEAM_MAP.get(category, "tier-1-support"),
        "reasoning": (
            f"Category '{category}' matched keywords in title/description. "
            f"Severity from priority_hint: '{priority_hint}'."
        ),
    }
```

## Step 5 — Wire the gateway

Write the gateway route config and Compose file. The gateway handles authentication and audit logging; your service handles only triage logic.

```yaml title="my-triage-service/routes.yaml"
# Ticket triage — gateway route configuration.
# Maps POST /tickets/{id}:triage to the triage service.
# No tenant required for this demo endpoint.
# Set tenantRequired: true + roles: [...] for production.

routes:
  - id: triage-endpoint
    method: POST
    path: /tickets/{id}:triage
    target: http://triage:8080
    tenantRequired: false
    audit: true
```

```yaml title="my-triage-service/docker-compose.yml"
# Ticket triage — Docker Compose
# ports: 8120 (gateway), 8121 (triage service)
#
# SECURITY NOTE: GATEWAY_JWT_SECRET is a DEMO-ONLY value.
# Replace with GATEWAY_JWT_JWKS_URL in production.

name: my-triage-service

services:
  yaagents-gateway:
    image: ghcr.io/ai-mpathyminds/yaagents-gateway:0.3.0
    ports:
      - "8120:8080"
    environment:
      GATEWAY_PORT: "8080"
      GATEWAY_ROUTES_FILE: /etc/yaagents/routes.yaml
      GATEWAY_JWT_SECRET: "demo-secret-not-for-production"
      GATEWAY_AUDIT_LOG: stdout
    volumes:
      - ./routes.yaml:/etc/yaagents/routes.yaml:ro
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://localhost:8080/healthz"]
      interval: 10s
      timeout: 5s
      retries: 3
      start_period: 5s
    networks:
      - triage-net
    depends_on:
      triage:
        condition: service_healthy
    restart: on-failure

  triage:
    build: .
    ports:
      - "8121:8080"
    environment:
      PORT: "8080"
    healthcheck:
      test: ["CMD", "python3", "-c",
             "import urllib.request; urllib.request.urlopen('http://localhost:8080/healthz')"]
      interval: 10s
      timeout: 5s
      retries: 3
      start_period: 15s
    networks:
      - triage-net
    restart: on-failure

networks:
  triage-net:
```

Write the Dockerfile:

```dockerfile title="my-triage-service/Dockerfile"
FROM python:3.12-slim

WORKDIR /app
COPY pyproject.toml .
COPY src/ src/
COPY data/ data/

RUN pip install --no-cache-dir -e .

EXPOSE 8080
CMD ["uvicorn", "triage.app:app", "--host", "0.0.0.0", "--port", "8080"]
```

### Example B — Clarification required

`TKT-004` is missing `priority_hint`. Your service returns `clarification_required`:

```bash
curl -s -X POST http://localhost:8120/tickets/TKT-004:triage \
  -H "Authorization: Bearer demo-token" \
  -H "Content-Type: application/json" \
  -d '{}'
```

```json title="Response — 400 Bad Request (application/vnd.yaagents.clarification+json)"
{
  "type": "clarification_required",
  "message": "A priority hint would improve triage accuracy. Please provide one or re-submit without it to use the default.",
  "requiredInputs": [
    {
      "name": "priority_hint",
      "location": "body",
      "type": "string",
      "required": false,
      "question": "What is the urgency level?",
      "allowedValues": ["low", "medium", "high", "critical"]
    }
  ]
}
```

Notice the HTTP status is `400` and the Content-Type is `application/vnd.yaagents.clarification+json` — any yaagents client (Python, TypeScript, Go) will detect this as a `clarification_required` outcome without parsing the body text.
