# ADR PI3-yaa-0004 — Pages site on GitHub Pages at `ai-mpathyminds.github.io/yaagents/`

Status: [Accepted]
Date: 2026-06-02
PI: PI3-yaa
Deciders: yaagents-architect (ratifies user-direct decision 2026-06-02; LOCKED in
`portfolio/INTAKE/PI3-yaa-intake.md` §A-5 — **revised 2026-06-02 from Cloudflare Pages**)

## Context

PI3-yaa is the public-launch PI. Per PRD §1 Goals + §5.11, a community-facing docs site must be
live at launch: `https://<host>/<path>` serving the 10 MVP sections (Hero, Why, Quick Start,
Profile Spec, 6 SDK Quickstarts, 2 Examples, Plugin Authoring, Public Roadmap, Contributing,
Community).

Two hosting paths were considered:

1. **Cloudflare Pages** + `yaagents.dev` custom domain — initial seed proposal (`yaagents-v0.3.seed.md`
   §A-5 first draft). Requires: custom domain purchase (~$15/yr); Cloudflare account setup
   (free tier sufficient); DNS records (A/AAAA → CF Pages IPs); CF Pages project + build
   pipeline; CF-managed TLS.
2. **GitHub Pages** at `ai-mpathyminds.github.io/yaagents/` — project-pages mode; no
   custom domain; GitHub-managed `*.github.io` TLS; build via GH Actions
   `actions/deploy-pages@v4`.

Two open questions:
- Is the custom-domain cost ($15/yr + operator time on DNS + CF account) justified pre-traction?
- Is the GitHub Pages project-pages URL good enough for community discovery + SEO at v0.3?

## Decision

1. **Host on GitHub Pages at `https://ai-mpathyminds.github.io/yaagents/`** (per intake §A-5
   LOCKED, revised 2026-06-02). Project-pages mode (`<org>.github.io/<repo>/` URL); meta-repo
   named `yaagents`; Astro `base: '/yaagents'` config matches.

2. **Custom domain (`yaagents.dev` or similar) is DEFERRED post-traction.** Re-open the
   decision when OSS adoption warrants the spend (PI4-yaa or later). The migration is a
   1-WI scope (intake §A-5 §Migration): buy domain → add `CNAME` file to
   `docs/public/CNAME` → update DNS (A/AAAA records to GitHub Pages IPs OR CNAME to
   `ai-mpathyminds.github.io`) → update Astro `site:` (drop `base:` subpath) → toggle "Enforce
   HTTPS" in repo settings. Estimated 1-2h of work; no rewrite of site content or build pipeline.

3. **Build + deploy via `.github/workflows/pages.yml`** at meta-repo root (PG-8 WI). Uses
   `pnpm/action-setup@v3` + `actions/setup-node@v4` + `pnpm install --frozen-lockfile` +
   `pnpm build` (Astro Starlight build) + `actions/configure-pages@v5` +
   `actions/upload-pages-artifact@v3` + `actions/deploy-pages@v4`. Triggered on push to `main`
   for paths under `docs/**` / `spec/**` / `schemas/**` / `openapi/**` + manual dispatch.

4. **Astro config**:
   - `site: 'https://ai-mpathyminds.github.io'`
   - `base: '/yaagents'`
   - These two settings produce internal links that work both locally (`pnpm dev` →
     `localhost:4321/yaagents/`) and in production (`ai-mpathyminds.github.io/yaagents/`).

5. **TLS = GitHub-managed `*.github.io` certs.** Zero operator config; GitHub auto-provisions
   and renews. No certbot, no Let's Encrypt setup.

6. **No analytics; no cookies; no third-party trackers.** Privacy-first per intake §A-5 +
   PRD §5.11. Adoption tracking happens via GitHub stars, PyPI/npm download stats, and GHCR
   pull counts (registry-side, not site-side).

7. **Adoption signal for moving to custom domain**: defer the decision until ≥1 of:
   - GitHub repo passes 500 stars
   - npm or PyPI monthly downloads ≥1000
   - External contributors land ≥3 PRs in any single PI
   When the signal trips, open a separate WI in a future PI to migrate per intake §A-5
   §Migration steps.

## Consequences

- **$0 hosting cost** at v0.3 launch. Aligns with PI3-yaa intake `Constraints` "≤$150/mo AWS
  run-rate ceiling preserved; CF Pages + yaagents.dev domain ~$1/mo total" — even the $1/mo CF
  Pages cost is eliminated by GitHub Pages free tier on project-pages mode.
- **GitHub-managed TLS** — no certificate lifecycle to maintain. No DNS gymnastics.
- **Lower discoverability** — `ai-mpathyminds.github.io/yaagents/` is less memorable than
  `yaagents.dev`. Mitigated by SEO via README badges, GitHub topic tags, PyPI/npm package
  descriptions, and (eventually) community-shared links. Acceptable for v0.3 community-launch
  scope.
- **Migration path is cheap** — when traction warrants, the move to custom domain is a 1-WI
  follow-up: no content rewrite, no build-pipeline rewrite, just DNS + CNAME file + Astro
  `site:` + `base:` config edit + "Enforce HTTPS" toggle in repo settings. Reversible if
  needed (DNS revert + config revert).
- **No CF account dependency** — keeps the launch surface to "things AmpathyMinds already has"
  (GitHub org + AWS account); no new vendor relationship to maintain at v0.3.
- **Astro Starlight default theme** — no custom design work; matches `web/corporate` Astro
  precedent (per `portfolio-conventions.md` `web/corporate` lane note); A-2.5 UX-architect
  station skipped per planning runbook `context.ux_a25_skip_evidence`.
- **Path-based subpath URL** (`/yaagents/`) is the only practical artifact of the
  project-pages mode. The Astro `base:` config absorbs it transparently — internal links use
  `<a href="/quickstart/">` and resolve to `/yaagents/quickstart/` at deploy time. No
  per-page-link rewriting in the content authoring.

## Alternatives

- **Alternative A (rejected — Cloudflare Pages + `yaagents.dev` custom domain)**: initial seed
  proposal. Rejected per user-direct 2026-06-02 "cost-conscious framing — use what GitHub
  gives us until we need more". CF Pages would require: domain purchase + CF account setup +
  DNS configuration + CF Pages project — none of which add launch value at pre-traction
  v0.3 stage.
- **Alternative B (rejected — Mintlify or other premium docs platform)**: paid hosted-docs
  platforms (Mintlify, Vercel paid tier, Docusaurus on Vercel free). Conflicts with free-tier
  posture; locks docs into a vendor; rejected at intake §A-5 + PRD §1 Non-goals.
- **Alternative C (rejected — README-only, no Pages site)**: no separate Pages site at v0.3;
  expand the meta-repo `README.md` to cover all 10 sections. Rejected per PRD §1 Goals — a
  10-minute quickstart needs more depth than a README can comfortably carry; community
  navigation expects a `/quickstart/` URL, not a scroll to a README section.
- **Alternative D (rejected — Astro on Cloudflare Workers)**: deploy via CF Workers instead of
  CF Pages. Workers add edge-compute capability the site doesn't need (static HTML is
  sufficient); rejected on simplicity grounds.
