# ADR PI1-yaa-0005 — Public publishing via OIDC trusted publishing

Status: [Accepted]
Date: 2026-05-17
PI: PI1-yaa
Deciders: yaagents-architect (SBOM format = platform-engineer A-4, OQ-5)

## Context

PI1-yaa publishes 3 PyPI packages, 1 npm package, and 1 multi-arch GHCR image.
The portfolio mandate (CLAUDE.md, NFR §10) is **no long-lived registry tokens
in CI** — OIDC trusted publishing everywhere. OQ-5 (SBOM format) is open.

## Decision

1. **PyPI**: GitHub Actions + **PyPI Trusted Publisher** (OIDC), one publisher
   registration per project (`yaagents-fastapi`, `yaagents-client`,
   `yaagents-cli`). `pypa/gh-action-pypi-publish` with `id-token: write`. **A
   TestPyPI publish gates the production publish** (publish job is two-stage).
2. **npm**: GitHub Actions + **npm provenance** (`npm publish
   --provenance`) via OIDC; no `NPM_TOKEN` secret. Public scoped package
   `@yaagents/client`.
3. **GHCR**: `docker/build-push-action` multi-arch (`linux/amd64`,
   `linux/arm64`) authenticating via the workflow's `GITHUB_TOKEN` OIDC to
   `ghcr.io` (`packages: write`); no PAT. Tags `0.1.0` + `latest`.
4. **SBOM ships PI1-yaa; Cosign deferred to PI2-yaa.** An SBOM is generated at
   image publish and attached to the GitHub Release. **SBOM format is a
   platform-engineer A-4 decision (resolves OQ-5 routing)** — Syft/SPDX-JSON
   vs CycloneDX is recorded in the REL-5 NFR body, not here. Cosign signing +
   SBOM attestation hardening are explicitly PI2-yaa (PRD §11).
5. **Trust pin**: OIDC `sub` / environment conditions pinned to the yaagents
   repo `main` + tag refs; release publish triggers on a `v0.1.0` tag.
6. **Schemas/OpenAPI**: attached to the GitHub Release as a versioned archive
   (no separate registry); stable spec URLs are post-PI1-yaa.

## Consequences

- REL-3/4/5/6 WIs encode these mechanics; platform-engineer refines NFR +
  picks SBOM format at A-4.
- Zero long-lived secrets in the yaagents repo CI — verifiable at PC-6.
- Three PyPI Trusted-Publisher registrations are a pre-publish external setup
  step (Phase-B WI dependency; no token in repo).

## Alternatives considered

- *API tokens in GH Secrets* — rejected: violates the no-long-lived-token
  portfolio rule.
- *Single combined publish workflow* — rejected: per-target jobs isolate
  blast radius and let one registry fail without blocking others.
- *Cosign in PI1-yaa* — rejected: PRD §11 defers signing/attestation to
  PI2-yaa; SBOM-attach is the PI1-yaa supply-chain floor.
