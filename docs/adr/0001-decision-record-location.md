# ADR 0001 — Decision records live in `docs/adr/`, in the repository, not on the site

Status: Accepted (proposed by the architect agent; ratified by the reviewer who merges it)
Date: 2026-09-10
Work item: `01a089f7-38cb-7cab-aee6-24eae1b06d37` · Packet: `01a089f7-fae4-7934-b546-766c86972d46`
Supersedes: nothing. The retired internal records are not superseded by this one; see *Context*.

## Context

This repository used to keep its decision records at `docs/adr/`, with ids of the form
`ADR PI3-yaa-0004`. Commit `432d216` removed all fourteen of them from the tree, together with
the per-cycle planning folders, as part of the public-launch scrub (ADR PI3-yaa-0003). The
rules they set are still enforced, and the workflows under `.github/workflows/`,
`CONTRIBUTING.md` and `docs/README.md` still cite them by id — but nothing a reader can open
in the tree explains them any more.

The operator has retired those records and settled that new ones go in `docs/` of this
repository. What they did not settle is whether a record is a page on the public site or a
file in the repository. That matters here because `docs/` is not a document folder; it is an
Astro Starlight site, and it has two areas that behave differently:

- **`docs/src/content/docs/**`** is the `docs` content collection
  (`docs/src/content/config.ts`). Every file there is built into a public page at
  `https://ai-mpathyminds.github.io/yaagents/`, and appears in navigation only through the
  hand-written sidebar in `docs/astro.config.mjs` — which already has an *Architecture* group.
- **Everything else under `docs/`** is not built. `docs/README.md` is the existing example.

`.github/workflows/pages.yml` does not tell the two apart. It triggers on `docs/**`: on a pull
request it builds the site and runs the Lighthouse budget, and on a push to `main` it builds
and redeploys. Any file added anywhere under `docs/` costs a site build, and on `main` a
redeploy, whether or not it adds a page.

The repository is public, so "repo-only" does not mean private. It means readable on GitHub
and not reachable from the site. Either way a record is subject to the same two gates in
`.github/workflows/supply-chain-audit.yml`, both of which scan every `*.md` in this
repository: Check B (`bin/yaagents-public-mirror-verify.sh`, the public-mirror scrub) and
Check C-1 (the superseded-licence string scan). Both run on push to `main` and on manual
dispatch — **not on pull requests**.

Every later record's landing path follows from the answer, which is why this one is first.

No requirement set came with this ask, so there is no stated NFR for this record to answer.

## Options considered

### A. Publish — each record is a Starlight page

A record would live at, for example, `docs/src/content/docs/architecture/decisions/0001-….md`,
carry Starlight frontmatter, and be listed in the sidebar.

- **For:** a community reader who only ever uses the site would find the records, next to the
  *Architecture* pages that already exist.
- **Against — every record becomes a build input.** It has to satisfy `docsSchema()`, pass
  `pnpm build` and the Lighthouse budget on its pull request; a malformed record blocks the
  deploy of everything else in the same push.
- **Against — the site is the product's user documentation.** A decision record carries the
  options that were rejected and, in time, decisions that were superseded. On the site, a
  superseded record reads as current guidance beside pages that describe what actually ships.
- **Against — two files per record.** The sidebar is listed by hand (only `sdks/` and
  `examples/` autogenerate), so each record either edits `docs/astro.config.mjs` or needs a
  new autogenerated group created first.
- **Against — not what this codebase did.** The retired records were never pages. They were
  plain Markdown at `docs/adr/`, and the site's *Architecture* pages explain how the system
  works, not why it was chosen.

### B. Repo-only — each record is a Markdown file at `docs/adr/`, outside `docs/src/`

- **For — the existing pattern.** Same folder and same plain-Markdown form as the retired
  records. The id shape differs (`0001` against `ADR PI2-yaa-0003`), so nothing collides.
- **For — it sits where the question is asked.** The places that cite a decision by id are CI
  comments, CI error messages, `CONTRIBUTING.md` and `docs/README.md`. Those readers are in
  the repository already; GitHub renders the Markdown one click from the citation.
- **For — it cannot break the site.** Nothing outside `docs/src/` is a build input.
- **For — still public.** Anyone can read and link a record.
- **Against — not reachable from the site navigation.**
- **Against — it still triggers `pages.yml`**, for no change to any page. See *Consequences*.

### C. Both — the repository file is the source, and the site renders it

Astro 5 (`docs/package.json` pins `astro ^5.18.2`) can load a folder outside `docs/src/` as a
second content collection. Not chosen now: it needs routes and a template written, and it
makes every record a build input again, which is option A's first cost. I have not tried it,
so its feasibility with Starlight `0.30` is a claim about Astro, not a tested one.

## Decision

**B.** Decision records for this product are repo-only:

1. A record lives at `docs/adr/NNNN-short-title.md` — plain Markdown, a four-digit sequence
   starting at `0001`, a kebab-case title, one decision per file.
2. Nothing under `docs/src/` is a decision record. Anything placed there is a public page.
3. The retired ids are neither reused nor renumbered. A new record that needs one cites it by
   its full id, in the `ADR PI2-yaa-0003` form.

## Consequences

- **What it costs is discoverability from the site.** A reader who never opens the repository
  will not find the records. The cheap mitigation is one link from the site's *Contributing*
  or *Architecture* page to the `docs/adr/` folder on GitHub. Not done here.
- **`pages.yml` does work for nothing on every record.** Each record's pull request runs a site
  build and the Lighthouse budget, and each merge redeploys an unchanged site. The fix is a
  separate change to the workflow: add `'!docs/adr/**'` after `'docs/**'` in both `paths`
  lists (GitHub Actions accepts a negated pattern after a positive one). `docs/grounding/`
  has the same exposure. Not done here.
- **The scrub gate applies to every record, and nothing checks it before merge.** Because
  Check B greps every `*.md` in this repository for the marker strings in
  `bin/yaagents-public-mirror-verify.sh`, a record cannot quote the retired internal document
  paths, and a retired id is safe only in the `ADR PI2-yaa-0003` form that script allowlists.
  Check C-1 likewise forbids the superseded licence's name. Both run on push to `main` only,
  so the reviewer is the only check a record gets before it lands. This is a live risk and
  not a hypothetical one — see *Found, not acted on*.
- **Option C stays open.** If the site ever should list the records, it can load them from
  `docs/adr/` without moving a file or changing an id.
- **The folder reuses the retired records' path.** The retired files remain readable in this
  repository's history at the parent of `432d216`, which is an ancestor of `origin/main`, so a
  later record that supersedes one of them can quote what it replaces.

## What I did not do

- **I changed nothing but this file.** `pages.yml`, `docs/astro.config.mjs`, the site pages and
  `CONTRIBUTING.md` are untouched; the link and the `paths` exclusion above are follow-ups.
- **I did not restore, migrate or rewrite any retired record,** or the CI comments that cite
  them by id.
- **I did not run `pnpm build`** to show that `docs/adr/` is left out of the site. That rests
  on the collection definition in `docs/src/content/config.ts` and on `docs/README.md`, which
  already sits outside `docs/src/` and is not a page.

  superseded licence's name does not appear.

  session did not have, so this record is in the working tree of
  `wakalix/wi-01a089f738cb` and not yet in a commit.
