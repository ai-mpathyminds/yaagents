# ADR PI1-yaa-0001 — Gateway architecture + internal-gateway lineage

Status: [Accepted]
Date: 2026-05-17
PI: PI1-yaa
Deciders: yaagents-architect (ratifies chief-architect seed direction)

## Context

`yaagents/gateway/` is a standalone Go reverse-proxy that adds authn,
tenant/actor context, route-level RBAC, audit, and **typed-response
passthrough** for the Agentic REST Profile. The portfolio already has two
internal generic gateways (`platform-services/gateway`, `ai-platform/ai-gateway`).
The lineage question: is the yaagents gateway a *consumer* of the internal
gateways, a *fork* of them, or a *net-new base*?

OQ-2 (PRD §13) also asks how dev-mode JWT validation works (HS256 vs mock JWKS).

## Decision

1. **The yaagents gateway is a net-new, standalone OSS codebase and the future
   BASE.** It does NOT depend on, vendor, or fork `platform-services/gateway`
   or `ai-gateway`. The intended convergence direction is the **reverse**: the
   internal gateways are later re-based on top of the public yaagents gateway
   (a separate future seed, NOT PI1-yaa scope, recorded in PRIORITIES). No
   cross-product import in either direction during PI1-yaa.
2. **Single small `net/http` + `httputil.ReverseProxy` core; zero heavy
   framework.** No Gin/Echo/Fiber. Rationale: the gateway must stay a thin,
   auditable, OSS-readable proxy; future internal re-base inherits a minimal
   surface.
3. **JWT validation (resolves OQ-2): support BOTH, config-selected.**
   `GATEWAY_JWT_SECRET` → HS256 symmetric (dev/demo default; Compose demo uses
   this). `GATEWAY_JWT_JWKS_URL` → RS256 via JWKS (production). Exactly one
   active per process; JWKS takes precedence if both set (warn-log). No mock
   JWKS server is built — HS256 is the demo path, which keeps the Compose
   topology to two containers.

## Consequences

- Gateway WIs (`docs/PI1-yaa/gateway.md`) cite this ADR for the
  net-new-base library justification (library-gates Gate 3).
- The internal re-base is unblocked but explicitly out of scope; the public
  surface (`routes.yaml` schema, env keys, profile header) is the contract the
  future re-base must preserve — treat it as semi-frozen at v0.1.
- HS256-default keeps the demo at 16 GB / two containers (NFR §10 dev ceiling).
- Cosign signing of the image is deferred to PI2-yaa (SBOM ships PI1-yaa).

## Alternatives considered

- *Fork an internal gateway* — rejected: couples a public OSS repo to private
  portfolio code and inverts the intended dependency direction.
- *Use Gin/Echo* — rejected: heavier dependency tree for a thin proxy; harder
  to audit for a source-available launch.
- *Mock JWKS server in the demo* — rejected: adds a third container and
  complexity for no PI1-yaa success-criterion gain.
