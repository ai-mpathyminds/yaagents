# ADR PI2-yaa-0003 — Apache 2.0 license flip (supersedes PI1-yaa-0004)

Status: [Accepted]
Supersedes: PI1-yaa-0004 (Dual-license source-available / fair-code)
Date: 2026-05-30
PI: PI2-yaa
Deciders: yaagents-architect (ratifies user-direct decision 2026-05-30)

> **Disclaimer (verbatim, GTM README §Appendix — carried over from
> PI1-yaa-0004 unchanged):** This includes a draft licensing strategy
> for product planning. It is not legal advice. Before publishing the
> license publicly or accepting external contributions, consult a
> qualified software licensing lawyer.

## Context

PI1-yaa shipped v0.1.x packages under the YAAgents Community License
(source-available; combined-AND threshold `<10 employees AND <USD 1M
revenue`) per ADR PI1-yaa-0004. User-direct decision 2026-05-30 flipped
this stance: v0.2.0 ships under Apache 2.0. The flip is tied to the
plugin-system + Go-client + ai-gateway-absorption work that defines
PI2-yaa (PRD §1 "Defect 2 — Non-OSI license gates community contribution"
and PRD §2 "Apache 2.0 license flip" capability).

Three sub-questions:
- Does v0.2.0 retroactively re-license the v0.1.x packages already
  published?
- What is the legal-review gate, and when does it bind?
- What artefacts ship under Apache 2.0 vs stay under the Community
  License?

## Decision

1. **v0.2.0 ships under the Apache License, Version 2.0** (PRD §8.1).
   `LICENSE` file at repo root contains the Apache 2.0 text byte-verbatim
   from PRD §8.2. `COMMERCIAL.md` is deleted (`git rm`). All v0.2.0
   source files carry the SPDX header `// SPDX-License-Identifier:
   Apache-2.0` + `// Copyright 2026 AimpathyMinds` (PRD §8.4).

2. **Non-retroactive boundary.** v0.1.x packages already published to
   PyPI / npm / GHCR stay under the YAAgents Community License (PRD §8.1
   "Non-retroactive boundary"). Users who need Apache 2.0 must upgrade
   to v0.2.0. There is **no re-license-and-republish** of v0.1.0
   artefacts. README carries the pointer block from PRD §8.3 explaining
   this non-retroactivity (verbatim).

3. **Legal review is a launch gate, not an engineering gate** (PRD §8.1
   "Legal-review-pending disclaimer"). PI2-yaa close (PC-6) is NOT
   blocked on counsel sign-off. The `legal-review-pending` banner in
   `CONTRIBUTING.md` travels with the WI body until counsel signs off;
   removal is a PC-6 non-engineering checklist item — not an engineering
   acceptance criterion. The disclaimer text is carried verbatim from
   GTM README §Appendix.

4. **Supersession of PI1-yaa-0004.** ADR PI1-yaa-0004 (Dual-license
   source-available) is `[SUPERSEDED]` by this ADR for v0.2.0+ artefacts.
   The combined-AND threshold (`<10 employees AND <USD 1M revenue`)
   becomes irrelevant — Apache 2.0 has no consumer-class gates.
   PI1-yaa-0004 remains historically authoritative for v0.1.x packages
   (frozen).

5. **Package metadata field updates** (all four registries):
   - PyPI: `License: Apache-2.0` + classifier `License :: OSI Approved
     :: Apache Software License` (REL-1).
   - npm: `"license": "Apache-2.0"` (REL-2).
   - GHCR: OCI label `org.opencontainers.image.licenses=Apache-2.0`
     (REL-3).
   - Go modules: standard `LICENSE` at module root suffices; `go.mod` has
     no explicit license field (REL-4).
   Every published package's `Supports-YAAgents-Profile` metadata is
   bumped to `v0.2` (BUMP-1a/1b/1c/2 + GOC-4 + gateway BUMP-3).

## Consequences

- v0.2.0 enables the community plugin flywheel (PRD §1 Defect 2 resolved)
  — Apache 2.0 is OSI-approved + the standard infra-OSS license; external
  contributors do not face a retroactive-payment risk.
- `COMMERCIAL.md` retirement is a deletion, not a soft-deprecation —
  the file is removed from git tree (LIC-1 acceptance).
- The `legal-review-pending` banner in `CONTRIBUTING.md` remains until
  counsel sign-off; chief-architect/user owns the removal at PC-6 (or
  later, depending on counsel timing).
- v0.1.x consumers are NOT forced to upgrade; they continue under the
  Community License indefinitely (the v0.1.x packages on PyPI/npm/GHCR
  are immutable artefacts). The README pointer block (PRD §8.3) carries
  the contact email for any v0.1.x licensing questions.
- Re-publish at 0.2.0 (REL-1/2/3/4) is a real WI set — license metadata
  in registry packages is part of the artefact, not just the source.
- A CI grep gate is added (REL-S NFR seeds + REL-6 CI matrix
  carry-forward): `grep -rn "YAAgents Community License" --include='*.go'
  --include='*.py' --include='*.ts'` returns 0 hits in any v0.2.0
  artefact source tree.

## Alternatives considered

- **Re-license v0.1.x retroactively** — rejected (user-direct intake
  decision): legally complex, requires reaching every v0.1.x consumer,
  and the artefacts on registries are immutable anyway. Clean SemVer
  break at 0.2.0 is the canonical pattern.
- **Stay on Community License + soften the threshold** — rejected: the
  PRD §1 Defect-2 framing (community contribution is structurally gated)
  cannot be solved by threshold tweaks; only an OSI-approved license
  resolves it.
- **Block PI2-yaa close on counsel sign-off** — rejected: counsel
  timelines are uncorrelated with engineering progress; engineering ships
  the artefacts with disclaimer text + launch (public re-announce, CLA
  removal) gates on counsel separately at PC-6.
- **Different OSI license (MIT / BSD-3 / MPL-2.0)** — out of scope for
  this ADR; user-direct intake specified Apache 2.0 explicitly. Any
  future re-license requires a new ADR.
